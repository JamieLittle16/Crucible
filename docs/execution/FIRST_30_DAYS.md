# First 30 Days

This is an aggressive sequencing target, not a promise. Evidence can force redesign.

## Days 1–3

Repository, pinned toolchain, lints, tests/benches, `xtask`, architecture guard, CI, component manifest skeleton.

## Days 3–7

In parallel:

- component capability resolver, profiles, trust/fidelity metadata, lockfile and generated composition;
- official source pin, class/method inventory, fingerprints, initial world dependency closure and Atlas commands.

## Week 2

Generated block-state data, source-backed section VARs, reference section, Uniform/packed/Local8/direct candidates, differential tests and first representation benchmarks.

## Week 3

Minimal `LiveChunkCore`, mutation-facts pipeline, summary/heightmap oracle work, bulk resolved world views and world-access benchmarks. Continue `ChunkAccess`, `LevelChunk`, `Heightmap`, persistence and wire excavation.

## Week 4

Ownership domains, transfer authority, generation/revision checks, typed effects, stage-stable reads, schedule perturbation, low-core measurements and M0 qualification review.

At day 30: PASS into M1, execute a bounded repair plan, or redesign before gameplay.
